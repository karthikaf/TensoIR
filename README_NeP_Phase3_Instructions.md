# Phase 3 Audit Report: Material-Aware Cone Sampling

This report documents the architectural modifications made to integrate **NeP Stage 2 (Material-Aware Cone Sampling)** directly into the TensoIR framework.

## 1. Architectural Implementations

### Step 3.1: Freezing Geometry (Stage 2 Switch)
- **Modifications**: Added `--stage 2` CLI argument via `opt.py` and implemented parameter freezing loops in `train_tensoIR_rotated_multi_lights.py`.
- **Purpose**: Mimics the exact NeP training setup. When Stage 2 is initialized from a Stage 1 checkpoint, it universally locks `requires_grad = False` across all geometric volume grids (Density Line, App Plane, Basis Matrix) and the initial Color MLP field. It exclusively leaves the BRDF MLPs (`renderModule_brdf`) and normal networks active.

### Step 3.2: Roughness-to-Cone Angle ($\theta_m$)
- **Modifications**: Added analytical evaluation inside `models/relight_utils.py` natively computing Equation 10 from the NeP paper: $\theta_m = \arctan(\text{roughness}^2 \times \sqrt{\beta/(1-\beta)})$.
- **Purpose**: Converts the physical property of Surface Roughness dynamically into a specular spread angle bounding radius where $\beta=0.9$ ensures 90% of the reflectance energy is captured.

### Step 3.3: Integrated Positional Encoding (IPE)
- **Modifications**: Created a pristine, zero-dependency `models/ipe.py` with `integrated_dir_enc`.
- **Purpose**: Standardized 3D direction vectors and variance (driven by $\theta_m$) into a Gaussian-attenuated multi-frequency shape matrix explicitly identical to Mip-NeRF's structural encodings, mathematically mapping spatial cone distributions to inputs usable by highly-constrained neural network models. 

### Step 3.4: Cone Environment Query & Replacing Hemisphere Integrals
- **Modifications**: Massively restructured `render_with_BRDF` in `models/relight_utils.py`.
- **Purpose**: 
  1. Built the `cone_sample_env` block to perform Monte Carlo Spherical Cap Sampling directly constrained by $\theta_m$ around the perfect reflection vector $R$.
  2. Substituted TensoIR's extremely slow `$O(128 \times bs)$` secondary hemispherical marching with a high-speed `$O(bs)$` linear vector transmittance evaluation (`compute_transmittance`).
  3. Fixed the rendering physics math: Separated standard numerical integration entirely for the direct light, and uniquely added the Cone Sampling response natively as the pre-integrated Specular Lobe modifier, preventing dangerous double-BRDF multiplication!

### Step 3.5: Apply S3IM Patch Loss (Stage 2)
- **Modifications**: Initialized `s3im_loss_fn` explicitly inside `train_tensoIR_rotated_multi_lights.py` based on existing CLI bounds, and applied it under the `relight_flag` block.
- **Purpose**: S3IM structurally forces pixel patches over the final PBR color outputs (`rgb_with_brdf_map`) against Ground Truth targets to penalize rendering noise, ensuring smooth, highly accurate physical material reconstructions across the entire Stage 2 timeline dynamically!

## 2. Testing & Execution Instructions

Because of the architectural changes to physically freeze shapes and independently train BRDF networks, executing the pipeline is now decisively structured into a two-stage process. 

*(**Note:** Ensure your terminal environment does not pipe `sys.stdout` invisibly; use `python -u` or natively activate `TensoIR` first to view structural evaluation chunks dynamically).*

### Stage 1: Build Phase (Geometry + Coloring)
Train the structural density tree from pure static noise until it solidifies (usually ~20k-40k minimum iterations for clean masking drops).

```bash
conda activate TensoIR
python -u train_tensoIR_rotated_multi_lights.py \
    --config configs/multi_light_rotated/[dataset_name].txt \
    --datadir ./Datasets/TensoIR_Synthetic/[dataset_name] \
    --nep_dynamic_weight 1 \
    --s3im_weight 1.0 \
    --n_iters 40000 \
    --progress_refresh_rate 10 \
    --expname [dataset_name]_phase3_stage1
```

### Stage 2: Material Physics (Cone Tracing + BRDF)
Freeze the base geometry checkpoint generated by Stage 1, bypass secondary ray integration loops with our optimized Cone approximations, and heavily train PBR gradients against the `S3IM` loss natively until completion.

```bash
conda activate TensoIR
python -u train_tensoIR_rotated_multi_lights.py \
    --config configs/multi_light_rotated/[dataset_name].txt \
    --datadir ./Datasets/TensoIR_Synthetic/[dataset_name] \
    --stage 2 \
    --ckpt ./log/log_rotated_multi_lights/[dataset_name]_phase3_stage1-[TIMESTAMP]/[dataset_name]_phase3_stage1.th \
    --nep_dynamic_weight 1 \
    --s3im_weight 1.0 \
    --n_iters 40000 \
    --progress_refresh_rate 10 \
    --expname [dataset_name]_phase3_stage2
```
*(**Note:** Simply point `--ckpt` to the literal timestamped folder generated inside your core logging directory from the successful completion of the Stage 1 architecture).*
